Exactly one mutation path

One faithful port of 2.9BSD's mkfs owns the allocator and the inode and directory writers; one engine owns every high-level operation. The batch commands, the interactive shell and the FUSE mount all call it, so a front end cannot invent a subtly different filesystem, and a fix lands once.

One structure, three byte orders

s5fs had the same layout on every machine that ran it — only the encoding of multi-byte fields followed the CPU. No host struct is ever laid over disk bytes, so PDP-11 middle-endian, VAX and little-endian, and big-endian images all come out of the same writer.

Byte fidelity, not “fsck is happy”

A filesystem writer has a large space of outputs that pass every check you would naturally write and are still wrong. So the checker shares no code with the writer, and a tape written here is validated and rebuilt by the era's own restor(8) under emulation.
